## 0. 全体像

```
マーケティング
├── 有料 … SNS広告(X / Meta / TikTok / YouTube)
└── 無料 … ① SNS運用
          ② 共有機能・バイラルデザイン
          ③ SEO / LLMO メディア
          ④ ASO(ストア最適化)
```

有料と無料は対立するものではなく、**フェーズで使い分ける**。
広告で初期ユーザーを入れて場を作り、その間に無料チャネル(SNS運用・メディア)を
育てる、という並走が基本形。

## 1. 貫く原則

### マーケティングの本質はテストである

「どの広告を使えばいいか」「どのSNSが正解か」に一般解はない。業界・ジャンル・
ターゲットによって刺さる媒体が変わる。**1日1テストでもいいから出して、数字を
取って分析する**。これを繰り返す以外に最適解に到達する方法はない。

したがって、施策は必ず「仮説 → 実施 → 数値 → 学び」の形で記録する
(`templates/test-log.md`)。反応がなかったという結果も収穫として扱う。

### 計測が無ければ、それはテストではない(施策0)【実践追記】

前項の裏返し。**アクセス解析・登録数の計測が入っていない状態で発信を始めると、
何が効いたのかを後から永久に復元できない。** 施策を並べる前に、まず数字が見える
状態を作る。これを「施策0」として、他のどの施策よりも先に置く。

最低限、次の3点が数字で見えること。

1. LP / トップページへの流入数
2. 登録・インストールなどのコンバージョン数
3. その後の実利用(1回でも中身を作ったか)

無料で始めるなら Cloudflare Web Analytics(cookie 不要)、Google Analytics、
アプリなら App Store Connect / Play Console の標準指標で足りる。

**注意**: 解析ツールを後から入れた場合、プライバシーポリシーの記述
(「解析ツールは使用していません」等)と最終更新日を必ず同時に直す。
ここを放置すると記載と実態が食い違う。

施策0は成功基準を数値で置けない(可否の問題)。**「LP のアクセス数が数字で
見える状態になっていること」のような達成条件で書く。**

### 有料 = 再現性、無料 = 時間(トレードオフ)

- **有料**: お金を払えば、狙った属性に対して短時間で再現性高く検証できる。
- **無料**: 投稿の時間帯・既存の影響力・運の要素でばらつく。本当は需要があるのに
  バズらない / 需要がないのに反応が出る、という誤判定が起きうる。

既存アカウントのフォロワー属性が、作ったプロダクトの層とずれている場合、
SNSを1から育てるには数ヶ月かかる。初速が欲しいなら小額広告が合理的。

### 数字が出ないとき、どこが壊れているかを切り分ける【実践追記】

「伸びない」は1つの問題ではない。ファネルのどこで落ちているかで、打つ手が
正反対になる。**発信量を増やす前に、必ず切り分ける。**

| 症状 | 壊れている場所 | やること |
|---|---|---|
| 流入がそもそも無い | 集客 | チャネル・訴求のテストを続ける |
| **流入はあるが登録されない** | **LP の訴求** | 発信を止め、LPを直す。集客を増やしても無駄 |
| **登録されるが使われない** | **オンボーディング / プロダクト** | 集客より先に中を直す |
| 使われるが継続しない | 提供価値 | ピボットを検討する |

太字の2行が重要。ここに該当するとき**発信量を増やすのは最も効率が悪い**。
集客の数字が出ているのに事業の数字が動かない場合、問題は集客ではなく
プロダクト側にあると判断し、時間の配分を移す。

30日後の判断表には、集客指標だけでなく **「流入 → 登録」「登録 → 実利用」の
転換率**を必ず入れる(`templates/marketing-plan.md` の7章)。

### 泥臭さと忍耐が成果を分ける

リリースして終わりではなく、毎日の機能追加・修正、毎日のいいね・コメント・
フォロー、コツコツした動画・記事作成。派手さはない。全自動でバズって即収益化と
いう事例はほぼ存在しない。**ユーザーにこの前提を隠さない。**

### 広められるチャンスがあれば広める

新しいSNS・プラットフォームを見つけたらすぐ試す。オフライン(友人・知人との会話で
その困りごとが出たら紹介する)も有効なチャネル。リアル経由はインストールまでの
距離が近く、知り合い伝いに広がる可能性がある。

## 2. ステージ別の優先順位

### S0 検証前(まだ作っていない / 作りかけ)

**やること: 作る前に広告で需要検証する。**

1. 生成AIで訴求画像(クリエイティブ)を作る
2. ランディングページ+ウェイティングリスト(メール登録)を用意する
3. 小額広告を出して、登録数とCPAを見る

これで得られるもの:

- **需要があるかの判定**。CPAが高い(=燃費が悪い)なら、そもそも需要がないと
  判断してピボットできる。作ってから気づくと、開発時間がまるごと無駄になる。
- **ローンチ時に使える見込み客リスト**。ウェイティングリストに「リリースしました」と
  告知すれば、登録者のうち一定割合(発信者の体感で7〜8割)がインストールに繋がる。
  100人集めれば70〜80インストールが初日から見込める。

注意: 作ろうとしているアイデアすべてに広告費をかけると総額が膨らむ
(1案5,000〜10,000円 × 5案 = 5万円)。検証したい案は絞る。

### S1 初期(リリース済み・ユーザー0〜100)

- 小額のターゲティング広告で初期ユーザーを投入する
- 同時に、ゼロからのSNS運用を立ち上げる(下記「SNS運用」)
- ASOの最低限(スクショ1〜2枚目、キーワード)を整える

SNS系・コミュニティ系プロダクトでは、ユーザーが投稿してくれる状態を先に作らないと
プロダクトが成立しない。この場合の初期ユーザー投入は特に価値が高い。

### S2 成長(ユーザー100〜1000)

- **共有機能とバイラルデザイン**を実装する(ユーザー自身に広めてもらう)
- 反応が取れたクリエイティブ・切り口を**他チャネルへ横展開**する
- レビュー数が増えてきたら、それ自体を社会的証明としてASOに反映する

### S3 拡大

- SEO / LLMO メディアを本格的に育てる(効果が出るまで数ヶ月かかるため、
  実際には S1〜S2 のうちから裏で仕込み始めるのが望ましい)
- ASOの継続改善、アップデート頻度の維持
- 多言語・海外展開

## 3. 有料:SNS広告

### 使える媒体

X広告 / Meta広告(Facebook・Instagram・Threads)/ TikTok広告 / YouTube広告。
媒体ごとの始め方と注意点は `channel-guide.md` を参照。

### 媒体の選び方

プロダクトの「魅力が伝わる形式」で選ぶ。

- **ゲーム、動きのあるUI** → 動いている様子を見せる必要がある。TikTok・YouTubeの
  動画広告。静止画中心の配信面とは相性が悪い。
- **管理・可視化系アプリ** → 一画面で価値が伝わる。X・Meta・TikTokいずれも可。
- **幅広い年齢層(高齢層を含む)** → SNS広告だけでは届かない層がある。
  マス広告が選択肢に入るのは相応の利益が出ている段階。

### 予算の考え方

- **最初は小額から。5,000円〜10,000円の範囲**で1回試す。
- 反応がなくても「反応がなかった」という結果が得られた時点で収穫。
- 広告に触れてダッシュボードの操作に慣れること自体が資産になる。

### CPA(Cost Per Acquisition = 1人獲得あたりのコスト)

CPAが高いほど燃費が悪い。多くの燃料を投下しても火がつかない状態。

| 対象 | 目安 |
|---|---|
| ウェイティングリスト獲得 | 100〜300円 |
| スマホアプリのインストール | 100円以内に収まることもある |

発信者の実測例(あくまで一例):

- 需要検証フェーズ: Meta約5,000円 + X約5,000円 = **合計約1万円で
  ウェイティングリスト67件**
- リリース後のX広告(ウェブサイトトラッキング設定): **約4,200円で約20万
  インプレッション、1日でインストール+60人程度、CPA約30円**

CPAはプロダクトの属性とクリエイティブで大きく変わる。ありきたりなToDoアプリ・
習慣化アプリのような差別化のないものは、同じ予算でも獲得数が伸びにくい。

### 横展開

ある媒体で反応が取れた広告クリエイティブは、他媒体でも反応が出る可能性が高い。
1本当たったら必ず横展開する。

## 4. 無料①:SNS運用

### ゼロフォロワーからの立ち上げ

目新しい裏技はない。**狙ったターゲット層に対して、毎日地道に反応していく。**

- 対象アカウントの投稿に **いいね / コメント / フォロー / 引用リポスト**
- 効果の強さ: いいね < 引用リポスト・コメント・フォロー
  (返報性の原理が働きやすい。特に公式アカウントからの反応は喜ばれる)
- いいねを起点にプロフィールへ流入する導線ができる
  → **プロフィールに「こういうアプリを作りました」+ リンク**を必ず置く
  (プロフィールの見せ方が獲得率を左右する)
- 自分の投稿は **build in public**(実装した機能、ダウンロード数の節目、
  数字の推移)が題材にしやすい

### 自動化の線引き

- **1対1のやり取りが発生する運用(リプライ・コメント返信)のAI全自動化は避ける。**
  返信も投稿もワンパターンになり、AI生成だと気づかれた時点でアカウントの信頼を
  失う。
- **不特定多数向けのコンテンツ(動画・記事)のAI生成は有効。** ユーザーと濃い関係を
  築く必要がないメディアなら、生成AIの活用は合理的。

### 動画SNS(TikTok等)

- AI生成のUGC風動画は作れる(HeyGen等。15秒生成で数百円規模。APIを直接叩けば
  安くなる)。ただし再現性は未確立で、検証が必要な領域。
- **無理にAI動画にせず、アプリの実操作を画面録画して上げるだけでも十分**。
  主要機能・見せたいデザインを録画し、「こういうアプリをリリースしました」と
  投稿するほうが反応が良い場合がある。
- **画像スライド投稿(複数画像)が動画より伸びやすいことがある。**
  動画で伸びないときは画像スライドを試す価値がある。
- どちらが効くかはテストで決める。

### チャネルは並列に置かず、供給元と展開先で組む【実践追記】

複数チャネルを「同時にやること」として並べると、稼働が割れて全部が中途半端に
なる。**1つを供給元(コンテンツを作る場所)、他を展開先(割って流す場所)として
組む。**

例:

- **note 1本 → X 3〜5ポストに割れる。** 長文で「なぜこう作ったか」を書き、
  その中の主張・数字・失敗談を単発ポストに分解する。ネタ切れが起きにくい
- **1本当たった訴求 → 他チャネル・広告クリエイティブへ横展開**(前述)
- **開発の作業ログ・ハマった罠の記録 → 記事の素材**。開発中に残したメモが
  そのままコンテンツ資産になる

週あたりの稼働時間から逆算し、**主軸は1つに決める**。週3〜5時間なら2チャネルが
上限、3本以上は回らない。

## 5. 無料②:共有機能とバイラルデザイン

### 共有機能

**紹介が紹介を呼ぶ仕組みをアプリ内に実装する。** 報酬を出すアフィリエイト型に
しなくてもよい。ユーザーが作ったコンテンツ・記録を、SNSやリンクコピーで
共有できるボタンを置くだけでも、ユーザー自身がマーケティングを代行してくれる
状態になる。実装していない個人開発アプリは多く、費用対効果が高い。

### マルチプレイヤー製品の落とし穴【実践追記】

共有・コラボレーション前提のプロダクト(共有メモ、チーム管理、SNS等)には、
初期集客に固有の罠がある。

**1人で登録しても価値が出ないため、集客した人がそのまま離脱する。**
「SNSで見て登録 → 一緒に使う相手がいない → 何もせず離脱」という流れが起きる。
このとき数字上は「集客はできているのに使われない」に見えるが、原因は
オンボーディングでも訴求の弱さでもなく、**製品が1人では成立しないこと**にある。

対策: **訴求の入口を「1人でも成立する用途」に寄せる。**

- 共有メモアプリ → 「学習記録」「資格試験の勉強ログ」「読書メモ」など個人利用の型
- チーム管理ツール → 「個人のタスク管理」から入れる
- SNS的プロダクト → 1人でも投稿する動機がある使い方を提示する

「みんなで使えます」は**入口では言わない**。共有は、使い始めた人が招待導線から
自然に広げるもの(前述の共有機能・バイラルデザインが効くのはこの段階)。

### バイラルデザイン

**アプリ内に「スクショされる画面」を1つ以上作る。**

- SNSでシェアされることを前提に設計した画面のこと
- 例: 月にいくら払っているかの一覧、登録中サービスの可視化画面、
  カレンダーの日付ごとに写真を埋めて思い出を並べる画面
- ポイントは「共有してください」と頼むのではなく、**ユーザーが自ら共有したく
  なる**画面を作ること
- 一目で「いいな」と思わせるデザインは、ローンチ時の反応にも直結する

設計時のチェック:

1. その画面はスクリーンショット1枚で価値が伝わるか
2. 個人情報がそのまま写り込まないか(共有時にマスクできるか)
3. アプリ名やロゴが自然に写り込むか(出所が伝わるか)

## 6. 無料③:SEO / LLMO メディア

### やること

Webサービスならサイト内にブログ機能を追加する。スマホアプリでも、別途Webメディアを
独自ドメインで立ち上げてよい。記事の中や末尾に自分のアプリを紹介する導線を置き、
検索流入からインストールに繋げる。

### 記事の作り方

**検索から逆算する。** ターゲットが検索しそうなワードのカテゴリを丸ごと押さえる。

例(サブスク管理アプリの場合): 「サブスク 解約」「サブスク 管理 方法」など、
そのカテゴリの検索ワードを洗い出し、それぞれに記事を用意する。

Claude Code のようなAIコーディング環境を使えば1日に数十本の記事生成も可能。
不特定多数向けのコンテンツなのでAI生成が向いている領域。

発信者の実例: サムネイル生成サービスについて記事を40〜50本生成 → 以降ほぼ
更新していないが、毎月安定した集客と月6万円程度の収益を継続(市場環境の変化で
逓減はする)。

### 時間軸

**中長期施策。** 書いてすぐインデックスされるわけではなく、上位表示までに
2〜3ヶ月かかる。初期ユーザーは広告・SNS運用で集めつつ、裏でメディアを育てる。

### LLMO / AEO

ChatGPT・Claude などのAIから推薦されるための最適化。ユーザーがAIに聞いて出てきた
リンクからサービスを使い始める流れが増えているため、メタデータを含めた対策は
やっておく価値がある。ただし即効性はない。

## 7. 無料④:ASO(App Store 最適化)

最低限、次の2つを押さえる。

### ① スクリーンショット / プレビューの見直し(最重要)

- **1枚目と2枚目が最も重要。** ストアの検索結果でパッと見えるのがこの2枚。
  スマホ画面での見え方で確認する。
- **社会的証明を入れると効果が高い。** ただし**実際に達成した事実のみ**。
  - カテゴリランキング1位を取っていないのに「1位」と書くのは不可
  - 1位が難しければ「100ダウンロード突破」「1,000ダウンロード突破」
    「投稿数1,000件突破」など、出せる数字を出す
  - 「たくさん利用されている」ことが伝われば目的は果たせる
- アップデートのたびに差し替え・入れ替えを検討する

### ② キーワード・カテゴリ・メタデータの見直し

- カテゴリ設定、キーワード欄、説明文のメタデータを定期的に見直す
- App Store Connect を扱うMCPサーバー(非公式)が存在するため、キーワード設定の
  相談・自動化に使える場合がある

### ③ アップデート頻度

更新が頻繁なアプリは評価が上がりやすいとされる。リリースして終わりにせず、
改善を重ねる。多言語対応による海外展開も拡大手段。

## 8. 数値の目安(まとめ)

| 項目 | 目安 | 備考 |
|---|---|---|
| 初回テストの広告予算 | 5,000〜10,000円 | 1媒体1回あたり |
| CPA(ウェイティングリスト) | 100〜300円 | これを超えたら需要または訴求を疑う |
| CPA(アプリインストール) | 100円以内も可能 | ニーズに刺されば数十円台も |
| ウェイティングリスト→インストール転換 | 7〜8割 | ローンチ告知メール経由 |
| SEO記事の効果発現 | 2〜3ヶ月 | インデックスと順位上昇に時間がかかる |
| SEO記事の本数感 | 40〜50本 | 1カテゴリを押さえる規模感 |

これらは発信者の実績・肌感覚に基づく参考値。自分のプロダクトの数値が出たら、
テストログの実測値を基準に置き換えていく。

## 9. AIにできないこと

需要検証(実際に市場に出すまで本当の需要は分からない)、リリース後のUI/UX改善、
ユーザーからのフィードバック対応、細かい使いづらさの修正 — これらは全自動化
できない。**8割はAIに任せ、残り2割のレビューと判断は人間が担う**、という前提で
計画を立てる。

新しいAIモデルが出ても、泥臭い作業なしにマネタイズできるようにはならない。
ニュースに反応し続けるより、目の前の検証サイクルを回すことに時間を使う。
